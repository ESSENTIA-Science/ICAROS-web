# CMS 자동 저장과 사이트 반영

## 멤버 프로필 사진

- 멤버를 선택한 뒤 **프로필 사진 업로드**에서 JPEG·PNG·WebP를 선택한다. 업로드가 확인되면 사진 연결이 자동 저장된다. **프로필 사진 제거**로 기본 아바타로 되돌릴 수 있다.
- **공개**가 켜진 멤버의 연결된 이미지가 전체 게시 빌드에 포함된다. 사진은 준비 완료된 이미지 파일만 허용하며, 비공개 멤버의 사진은 내보내지 않는다.
- 저장된 사진을 공개 웹에 적용하려면 우측 상단 **변경사항 반영하기**를 누른다.

## 본문 표와 이미지 배치

- 게시글과 미션 본문은 Markdown으로 저장한다. **표** 버튼에서 셀을 편집하거나 스프레드시트의 탭 구분 데이터를 붙여넣으면 GFM 표가 삽입된다. 기존 표 안에 커서를 놓고 버튼을 누르면 그 표를 다시 편집한다.
- **이미지 배치** 버튼에서는 여러 사진을 업로드하고 순서·대체 텍스트·캡션을 편집한다. 1·2·3열 배치를 고를 수 있고, 1열에서는 왼쪽·가운데·오른쪽 정렬을 선택할 수 있다. 이미 만든 갤러리 안에 커서를 놓거나 일반 Markdown 이미지 여러 개를 선택한 뒤 버튼을 누르면 그 이미지를 편집할 수 있다.
- 갤러리는 `:::gallery{columns=2}` 블록으로 저장된다. 블록 안에는 이미지 Markdown만 놓는다. 본문 이미지는 CMS의 `/api/media/<id>`를 사용하고, 게시 빌드에서 검증된 공개 URL로 치환된다. 공개 화면은 모바일에서 갤러리를 한 열로 표시한다.

- 기존 항목은 입력이 멈춘 뒤 약 0.7초 후 자동 저장된다. 같은 항목의 요청은 순서대로 처리하며 저장 도중 입력한 내용을 유지한다.
- 새 항목은 필수값이 유효해지면 비공개 초안으로 생성된다. 새 게시글·기체의 미완성 입력은 로컬 브라우저에도 보관된다.
- 항목·탭을 전환하거나 반영을 요청하기 전에 진행 중인 저장과 업로드를 완료한다. 필수값 누락 또는 저장 오류가 있으면 사이트 반영을 중단하고 오류를 표시한다.
- 우측 상단의 **변경사항 반영하기**가 전체 사이트 게시의 유일한 진입점이다. 안내창에서 확인하면 ESSENTIA 게시글 초안을 승격하고 전체 스냅샷으로 한 번 빌드한다.
- 반영 안내는 보통 1~2분이 걸리며 페이지를 유지하도록 요청한다. 실제 완료 여부는 게시 job 상태로 확인한다. 실패 시 기존 공개 사이트를 유지하며 재시도할 수 있다.
- 반영 중 입력한 새 수정은 미반영 상태로 남는다. 완료한 빌드에 포함된 변경만 반영 완료로 표시한다.
- 미반영 수정·저장·게시 진행 중 페이지를 닫거나 새로고침하면 브라우저 기본 종료 경고가 표시된다. 경고 문구는 브라우저가 정하며 임의의 alert 문구로 바꿀 수 없다.
- 변경 카운터와 진행 중 job ID는 브라우저에 보관하므로 새로고침 후에도 미반영 상태 및 job 추적을 유지한다.

API의 `POST /api/admin/publish`에는 기존 식별자·버전·멱등성 키에 `scope: 'all'`을 추가한다. 로컬 API는 소스 변경을 자동으로 다시 읽지 않으므로 현재 실행 중인 프로세스에는 사용자가 `dev.sh`를 재시작해야 적용된다. 이 작업에서 개발 서버 시작·재시작 및 운영 배포는 하지 않았다.
