# ICAROS-web — 조치 계획

부채 대장(`docs/icaros-rebuild/15-infra-debt.md`)이 인프라 항목을 이미 관리하고 있다.
이 계획은 **대장이 다루지 않는 것**과 **대장 항목 중 코드로 닫을 수 있는 것**만 다룬다.

---

## 8시간이 있다면

### 1. 저장소 비공개 전환 (5분) — 다른 무엇보다 먼저

| | |
|---|---|
| 영향 | **높음** — 실명 멤버 사진 8건이 공개 이력에 있다 (대장 B3 🔴) |
| 노력 | 5분 |
| 위험 | 없음 |

**HEAD에서 지워도 해결되지 않는다** — git 이력에 blob이 남는다.
**확산을 멈추는 것이 먼저**이고, 이력 정리는 그 다음이다.

이미 private이라면 이 단계를 건너뛰고 2번으로.

### 2. CI 워크플로 생성 (2시간)

| | |
|---|---|
| 영향 | **높음** — 커밋에서 프로덕션까지 자동 게이트가 `next build` 하나뿐이다 |
| 노력 | 2시간 |
| 위험 | 낮음 — 검사만 추가 |

**대상** 신규 `.github/workflows/ci.yml`
```yaml
on: { pull_request: {}, push: { branches: [main] } }
jobs:
  verify:
    steps:
      - uses: actions/checkout@<40자 SHA>
      - uses: actions/setup-node@<40자 SHA>
      - run: npm ci
      - run: npm run typecheck
      - run: npm run lint
```
**스크립트는 이미 있다. 트리거만 없다.**

배포 후 단계로 `npm run smoke` 를 추가하면 **대장 D2가 닫힌다** —
2026-08-30 장애에서 "스모크가 이 케이스를 갈랐겠지만 돌린 사람이 없었다"가 실증됐다.

### 3. `buildPoolConfig()` 회귀 테스트 (30분)

| | |
|---|---|
| 영향 | **높음** — 2026-08-27 장애의 재발 경로를 봉인한다 |
| 노력 | 30분 |
| 위험 | 없음 |

```bash
npm i -D vitest @vitest/coverage-v8
```
```ts
// src/lib/db/connection.test.ts
it('serverless pool stays small — 2026-08-27 incident', () => {
  const cfg = buildPoolConfig()
  expect(cfg.max).toBe(3)
  expect(cfg.idleTimeoutMillis).toBe(10_000)
})
```
지금은 **코드 주석이 유일한 방어**이고, 주석은 사람이 읽어야 작동한다.

### 4. 스키마 권한 **검증** 스크립트 (30분)

| | |
|---|---|
| 영향 | 중간 — 설계는 이미 정확하다. 적용 여부를 확인할 수단이 없을 뿐 |
| 노력 | 30분 |
| 위험 | **없음** — 읽기만 한다 |

> **정정** — 이 감사는 처음에 "GRANT/REVOKE가 없다"고 판단했으나 틀렸다.
> `DECISIONS.md` D17이 `icaros_app` role 설계를 담고 있고,
> D17 보정이 그 설계의 구멍 5개를 스스로 찾아냈다.

권한을 **바꾸는** 것이 아니라 **읽는** 스크립트를 만든다:
```
scripts/db/verify-grants.ts
  1) icaros_app 이 public 에 가진 권한        (기대: 없음)
  2) icaros 스키마의 default privileges       (기대: 마이그레이션 role 기준)
  3) has_schema_privilege(icaros_app, icaros, CREATE)  (기대: false)
```
`scripts/db/verify.ts` · `inspect-public.ts` 가 이미 있어 패턴이 마련돼 있다.
2번의 CI에 붙이면 **설계와 현실의 드리프트가 자동으로 잡힌다.**

D17 보정 ①이 지적한 `ALTER DEFAULT PRIVILEGES` 누락은
"다음 마이그레이션 후 배포가 깨진다"는 형태로 나타나므로,
이 스크립트가 **배포 실패를 미리 잡는다.**

**검증** 출력이 D17의 기대값과 일치하는지. 어긋나면 그 자체가 발견이다.

### 5. 죽은 `vite.config.js` 삭제 (5분)

`@vitejs/plugin-react` 와 `react-router-dom` 을 참조하는데 **둘 다 package.json에 없다.**
Next 이전 시대의 잔재이고 `port: 5174` 를 선언해 `npm run dev` 와 혼동을 만든다.

### 6. 남는 시간: `src/lib/auth/` 테스트 (3시간)

`guard.ts` 의 Origin 판정부터. self-origin 폴백을 제거한 판단이
회귀로 되돌아오는 것을 막는다.

## 3일이 있다면

위를 포함하고:

### 7. 운영 마이그레이션을 CI로 옮긴다 (반나절)

지금은 `npm run db:migrate` 를 개발자 노트북에서 `.env.local` 자격증명으로,
SSM 터널을 통해, 승인·기록 없이 실행한다.

마이그레이션 러너 자체는 잘 만들어져 있다 —
`drizzle-kit migrate` 가 실패를 삼키는 것을 발견하고 직접 구현했고,
파일당 단일 트랜잭션 · `--dry` 모드 · 해시 원장을 갖췄다.
**문제는 실행 위치뿐이다.**

2번의 CI에 배포 후 마이그레이션 단계를 추가하고, 로컬은 `--dry` 로만 쓴다.

### 8. 멤버 사진을 S3로 (반나절)

이미 S3를 쓰고 있다(`src/lib/s3/`). 이미지를 옮기고 코드가 URL을 참조하게 한다.
이력 제거(`git filter-repo`)는 강제 푸시를 동반하므로 별도 판단.
**당사자 동의 여부를 먼저 확인할 것** — 개인정보보호법상 사진은 개인정보다.

### 9. `src/lib/s3/cleanup.ts` 테스트 (반나절)

**잘못 돌면 살아 있는 파일을 지운다.** 되돌릴 수 없는 유일한 경로다.
막 업로드된 파일이 고아로 판정되지 않는 경계 조건이 핵심이다.

### 10. E2E 1개 + smoke 자동화 (반나절)

로그인 → 관리자 진입. `smoke` 를 Playwright로 옮겨 배포 후 CI에서 돌린다.

> 그리고 **우리에게는 알림 채널 자체가 없다** — 만들 것을 정하기 전에 그 사실부터 인정해 둔다."*

**코드 변경 0, 사람 결정만 필요하다.** 그리고 2026-08-30에 그 비용이 실측됐다
(40분 장애를 ICAROS는 아예 몰랐다).

### 13. 테스트 커버리지 확대

## 하지 않을 것

- **커넥션 추가 튜닝** — 대장이 기준(60 초과 시 진행)과 함께
  "하지 않는다"고 결정했고, 근거(현재 최대 36)가 타당하다.
  `max: 1` 은 커넥션 문제를 지연 문제로 바꿀 뿐이다.
- **PgBouncer / RDS Proxy** — 대장 A5가 "보류". 현 수준에서 필요하지 않다.
- **RDS 인스턴스 분리** — 대장 A4가 "비용·운영 부담이 크고 지금 정당화되지 않는다".
  대신 4번(권한 격리)으로 가장 큰 위험을 싸게 줄인다.
- **인증·DB 계층 리팩터링** — 감사 대상 중 가장 견고하다. 건드릴 이유가 없다.
