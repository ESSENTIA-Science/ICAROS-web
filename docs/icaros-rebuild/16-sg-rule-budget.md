# 16. RDS 보안그룹 규칙 예산 — 왜 59칸인가, 줄일 수 있나

조사 2026-08-28 · 전부 실측 (AWS CLI `--profile essentia` · ap-northeast-2 · ip-ranges `syncToken 1787879825`)
도구: `npm run infra:sg-plan` (읽기 전용 드라이런이 기본)

> 이 문서에 계정 번호 · 인스턴스 id · 보안그룹 id · RDS 엔드포인트를 적지 않는다. 공개 레포다.
> 실제 값은 `docs/.local/identifiers.md`.

---

## 결론

**59칸은 줄일 수 없다. 지금 방식으로는 오히려 234칸이 필요하다.**

Vercel Fluid Compute 에 고정 egress IP 가 없어서 **us-east-1 EC2 대역 전체**를 허용해야 하는데,
AWS 공식 목록이 295개 프리픽스(과잉포함 없이 병합해도 **234개**)다. 규칙 상한은 60이다.

그래서 지금은 **234개 중 59개만 골라 넣은 상태**다. 나머지 175개 블록은 빠져 있다 —
규칙을 다 쓰고도 정확하지 않다.

규칙 수를 실제로 줄이는 길은 하나뿐이다: **IP 허용목록을 그만두는 것.**
Vercel **Static IPs**(Pro, $100/월/프로젝트)를 켜면 59칸이 **2칸**이 된다.
돈을 안 쓴다면 보안그룹을 3개 더 붙여 234개를 정확히 채우는 것이 차선이고, 그건 **오늘 무료로** 가능하다.

---

## 1. 지금 60칸에 무엇이 있나

| | |
|---|---|
| 인바운드 규칙 | **60개 (만석)** |
| └ ICAROS Vercel egress | 59 |
| └ ESSENTIA EC2 (SG 참조) | 1 |
| 남은 자리 | **0** |
| 규칙/SG 쿼터 `L-0EA8095F` | 60 (조정 가능) |
| SG/ENI 쿼터 `L-2AFB9258` | 5 (조정 가능, 최대 16) |
| 두 쿼터의 곱 상한 | 1000 |

만석이라 개발 머신 IP 한 줄도 들어가지 않는다 — **§C4 가 막힌 직접적인 이유**다.

## 2. 왜 59개나 되는가

Vercel Fluid Compute 는 함수 인스턴스를 여러 개 띄우고 그 egress IP 는 **AWS us-east-1 EC2 대역
어디든** 될 수 있다. 고정 IP 가 없다. 그래서 "우리 앱"을 허용하는 유일한 방법이
"그 리전의 EC2 전부"를 허용하는 것이 된다.

**이건 보안 경계가 아니다.** 21,519,008개 주소를 여는 것이고 그중 아무 EC2 나 1분이면 빌릴 수 있다.
그럼에도 없애면 안 되는 이유는 기밀성이 아니라 **가용성**이다 — §4 선택지 D.

## 3. 지금 상태는 틀렸다 — 2.2% 가 비어 있다

| 항목 | 블록 | IP |
|---|---:|---:|
| 공식 us-east-1 EC2 (병합 후) | 234 | 21,519,008 |
| 현재 허용 | 59 | 21,053,440 |
| **미커버** | **175** | **465,568 (2.2%)** |
| 과잉포함 | 0 | 0 |

과잉포함이 0이라는 건 59개가 임의의 supernet 이 아니라 **정확한 234개 중 59개**라는 뜻이다.
넓게 뭉친 게 아니라 큰 것부터 담고 나머지를 버렸다.

빠진 175개 블록에 배정된 Vercel 인스턴스는 **조용히 타임아웃** 난다. RDS 로그에도 남지 않는다.
증상이 "간헐적 DB 지연"으로 보여 코드에서 원인을 찾게 된다 — **D27 이 기록한 함정이 아직 살아 있다.**

### CIDR 산수로는 풀리지 않는다

60칸에 맞추려면 얼마나 넓게 뭉쳐야 하는지 계산했다.

| supernet 상한 | 규칙 | 열리는 IP | 목표 대비 |
|---|---:|---:|---:|
| 병합만 (과잉 0) | 234 | 21,519,008 | 1.00× |
| /16 | 124 | 26,148,864 | 1.22× |
| /13 | 98 | 64,487,424 | 3.00× |
| /11 | 75 | 192,937,984 | 8.97× |
| **/9** | **50** | **528,482,304** | **24.56×** |
| /8 | 47 | 838,860,800 | 38.98× |

60 밑으로 내려가는 첫 지점이 `/9 · 50개`인데 그때 여는 범위가 목표의 **24.6배**다.
5억 개 주소를 열어 규칙 9칸을 아끼는 거래다. 하지 않는다.

## 4. 선택지

### A. Vercel Static IPs — 59칸 → 2칸 · **권장**

프로젝트에 고정 egress IP 쌍을 붙인다. 보안그룹에는 그 둘만 남는다. 구멍도 사라지고,
경계가 "us-east-1 EC2 전부"에서 "Vercel 공유 static IP 풀"로 좁아진다.

| | |
|---|---|
| 플랜 | **Pro 및 Enterprise** (Secure Compute 와 별개 기능) |
| 비용 | **$100/월/프로젝트** + Private Data Transfer(리전별 요금) |
| 커버 범위 | Vercel Functions egress 전부. **미들웨어(edge)는 제외** — 이 레포에는 `middleware.ts` 가 없으므로 DB 를 치는 트래픽 100% 가 이 경로다 |
| 빌드 트래픽 | 옵션. 이 앱은 빌드 시 DB 를 치지 않으므로 끈 채로 둔다 |
| 한계 | IP 를 같은 리전의 소수 고객과 **공유**한다(전용 아님). 전용은 Secure Compute = Enterprise |

### B. 보안그룹 3개 추가 — 구멍 0 · **오늘 무료로 가능**

RDS 에는 보안그룹을 5개까지 붙일 수 있다. 4개면 240칸이라 235개(우리 234 + ESSENTIA 1)가 들어간다.
**쿼터 상향 신청도 돈도 필요 없다.** 규칙 수는 늘지만 2.2% 구멍이 사라진다.

대가: AWS 가 대역을 바꿀 때마다 다시 맞춰야 한다. AWS 는 `AmazonIpSpaceChanged` SNS 로 알린다.
자동화하거나 분기마다 `npm run infra:sg-plan` 을 돌린다.

### C. RDS 를 인터넷에서 내린다

지금 RDS 는 `PubliclyAccessible=true` 다. VPC 안으로 컴퓨트를 옮기거나 Secure Compute 의 VPC
피어링으로 붙으면 5432 를 인터넷에 열 이유가 없어진다. **가장 옳은 끝 상태이고 가장 큰 변경.**
Secure Compute 는 Enterprise 전용이라 지금은 못 쓴다.

### D. `0.0.0.0/0` + IAM·TLS — **권하지 않는다**

59칸이 즉시 비고 구멍도 사라진다. 인증은 여전히 강하다(정적 비밀번호 없음, 15분 토큰).
그런데 **커넥션 슬롯 고갈은 인증 이전 단계에서 일어난다.** 이 RDS 는 ESSENTIA 와 공유이고
슬롯 포화는 이미 최대 현안이었다(D26 · `53300`). 지금 허용목록의 실질 가치는 기밀성이 아니라
**가용성**이고, D 는 그걸 버리는 선택이다.

## 5. 준비된 것

```bash
npm run infra:sg-plan            # 현재 상태·구멍·필요 SG 수. 아무것도 바꾸지 않는다
npm run infra:sg-plan -- --advice  # 선택지 해설
npm run infra:sg-plan -- --json    # 계획을 sg-plan.json 으로 (ESSENTIA 공유용)

npm run infra:sg-plan -- --apply --yes   # 선택지 B 적용
```

`--apply` 는 보안그룹을 필요한 만큼 만들어 RDS 에 **덧붙이고**(교체가 아니다), 빠진 175개를 채운 뒤,
다시 읽어서 구멍이 0인지 확인한다. 안전장치:

- 적용 전 현재 인바운드 전체를 `sg-rollback-<syncToken>.json` 으로 저장한다(이 파일을 못 쓰면 시작하지 않는다)
- `ICAROS Vercel egress` 로 시작하는 설명이 붙은 규칙 **외에는 건드리지 않는다** (ESSENTIA SG 참조 규칙 안전)
- **추가를 먼저, 삭제를 나중에** 한다 — 반대로 하면 그 사이 창에서 프로덕션이 끊긴다
- RDS 의 SG 목록은 덮어쓰기라, 기존 id 를 반드시 함께 넘긴다. `RDS_INSTANCE_ID` 없이는 부착을 거부한다
- 식별자를 코드에 박지 않는다 — 전부 환경변수·조회

## 6. 확인이 필요한 것 (사용자 결정)

1. **Vercel 플랜이 Hobby 인지 Pro 인지.** Static IPs 는 Pro 이상. Hobby 면 승급 비용이 먼저 든다.
2. **$100/월(연 $1,200)을 쓸 것인가.** 학생 팀 예산에서의 크기는 판단할 수 없다.
3. **ESSENTIA 통보.** 보안그룹도 RDS 도 공유 자원이다. B 든 C 든 상대 합의가 먼저다.
4. **프리픽스 갱신 주기.** B 를 고르면 AWS 대역 변경을 따라가야 한다 — 자동화 여부를 정해야 한다.

## 7. 곁가지 — C4 는 이 문제와 분리해 이미 풀렸다

로컬에서 RDS 에 붙는 문제(§C4)는 보안그룹을 건드리지 않고 해결됐다.

```bash
npm run db:tunnel                                                    # 터미널 1
DB_AUTH=iam PGTUNNEL_HOST=127.0.0.1 PGTUNNEL_PORT=5433 npm run dev   # 터미널 2
```

`src/lib/db/connection.ts` 가 **접속 주소와 신원을 분리**한다 — 접속은 SSM 터널로 가고
IAM 토큰 서명·TLS 인증서 대조는 실제 엔드포인트로 한다. 그래서 15-infra-debt.md 가 적어 둔
두 함정(`/etc/hosts` 수정, `sslmode` 강등)이 **둘 다 필요 없다.** 실접속으로 확인했다(2026-08-28).
