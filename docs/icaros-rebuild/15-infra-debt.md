## 0. 이번 incident 최종 결론

> 공유 RDS 에서 **ICAROS 의 배포·미디어 처리 과정이 순간적으로 많은 DB 커넥션을 생성**했고,
> ESSENTIA 백엔드의 커넥션까지 밀어내는 장애가 발생했다 (2026-08-27 12:27:45 KST).
>
> `/api/media` 의 불필요한 DB 조회 제거와 이미지 변형 수 축소를 적용한 뒤
> **최대 커넥션이 77 → 36 (−53%)** 으로 감소했고, 배포 후 **18시간 이상 FATAL 0건 ·
> 커넥션 알람 재발화 0회** 를 확인했다.
>
> 따라서 **추가 pool 축소(`max: 3 → 1`)는 하지 않고 현 설정을 유지한다.**
>
> 남은 cold fan-out · RTO · DB 노출 · 백업 · 감사/보안 · 테스트 문제는
> **별도 인프라 부채로 관리한다** (아래 §2).

### 상태 판정

| 항목 | 상태 |
|---|---|
| 커넥션 고갈로 인한 **서비스 영향** | **완료** — FATAL 0건, 알람 재발화 0회 |
| 커넥션 사용량 **완화** | **완화 성공 / 관측 단계** — 최대 36, 경고선 60까지 24 여유 |
| **cold fan-out 구조** | **미해결** — 배포 직후 스파이크는 여전히 발생. 다만 현 수준(36)에서 관측 유지가 맞다 |
| `max: 3 → 1` | **취소** — 기준(60 초과 시 진행)에 도달하지 않았다 |
| PgBouncer / RDS Proxy | **보류** — 당장 도입하지 않는다. 향후 구조 개선 후보로만 남긴다 |
| 두 최적화의 개별 기여도 | **분리 불가** — 같이 배포했다. 이를 위해 임의로 rollback 하지 않는다 |
| 추가 connection tuning | **하지 않는다** |

### 측정 근거

`essentia_infra` 제공. 1분 해상도, 표본 1,104개 (08-27 14:00 ~ 08-28 08:24 KST).

| | 배포 전 | 배포 후 |
|---|---|---|
| p50 | 10 | **10** |
| p90 | 13 | 16 |
| p99 | 28 | 26 |
| 최대 | **77** | **36** |
| `icaros_app` 슬롯 고갈 FATAL | **95건** | **0건** |
| `essentia@essentia` 거부 | 1건 | **0건** |
| 커넥션 알람 재발화 | — | **0회** |

**p50 이 10 그대로인 것이 핵심이다.** 그 10은 ESSENTIA Hikari 가 상시 쥐는 몫이고,
그 위에 얹히던 ICAROS 몫이 꼬리에서만 잘렸다 — 기저는 안 건드리고 꼬리만 깎았다.

배포 후 30을 넘긴 구간은 **2개뿐이고 둘 다 배포 시각 ±8분** 안이다. 이후 18시간 0회.
**"배포 직후 cold fan-out" 가설이 확정됐다.**

## 3. 별도 보안 이슈 — 멤버 사진이 public 저장소에 있다

**이번 DB incident 와 분리해서 관리한다.** 조사 중 발견됐을 뿐 원인·영향이 전혀 다르다.

### 사실

| | |
|---|---|
| 파일 | `public/assets/img/member/` **8개** (`.webp` 7 · `.jpg` 1) |
| 도입 | 단일 커밋 `138f39a` "ver 2" · 2025-12-22 |
| 저장소 | `ESSENTIA-Science/ICAROS-web` — **PUBLIC** (2025-12-21 생성) |
| **포크** | **1개 — `aidengoldkr/ICAROS-web`, public, 최종 push 2026-07-09** |
| 현재 사용 | 코드에서 참조하는 것은 `profile.webp`(플레이스홀더) 하나뿐 |
| 프로덕션 노출 | **있음** — `/member` 가 `/_next/image?url=/assets/img/member/*.webp` 로 서빙 중 (관측 확인) |

### 왜 모순인가

`/api/media` 는 `entity_type='member'` 를 캐시 허용목록에서 빼고 `private, no-store` 로 닫아 두었다.
사유는 **미성년자 얼굴**이다 (요구사항 I17). 그런데 **같은 얼굴이 public 저장소에 그대로 있다.**
캐시 정책이 막는 것을 저장소가 열어 두고 있다.

### ⚠️ 파일 삭제 커밋으로는 해결되지 않는다

`git rm` + 커밋은 **HEAD 에서만** 지운다. 과거 커밋에서 여전히 받을 수 있다.
"지웠다"고 생각했는데 안 지워진 것이 **이 사안에서 가장 나쁜 결말**이다.

실제 제거에 필요한 작업 — **전부 사용자 명시 승인 전까지 실행 금지**:

| 단계 | 내용 | 비고 |
|---|---|---|
| 1 | 현재 tree 에서 삭제 | 이것만으로는 불충분 |
| 2 | **history rewrite** (`git filter-repo` 등) | 모든 커밋 SHA 가 바뀐다 |
| 3 | **force push** | 기존 clone·PR·브랜치가 전부 어긋난다 |
| 4 | **포크 처리** | `aidengoldkr/ICAROS-web` 는 **별개 저장소**다. rewrite 가 전파되지 않는다 |
| 5 | **GitHub Support 캐시 삭제 요청** | 삭제된 객체도 한동안 SHA 직접 접근이 가능하다 |
| 6 | 기존 clone | **회수 불가.** 이미 받아 간 사본은 어떻게 해도 못 지운다 |

### 대안 — rewrite 없이 노출을 줄이는 경로

`unknown / verification required` 로 남긴다. 검토할 것:

- 사진을 S3(비공개) + `/api/media` 로 옮기고 저장소에서는 **새 커밋으로 삭제** — 히스토리에는 남지만 **현재 트리와 프로덕션 서빙 경로에서 사라진다.** 노출 표면이 "저장소를 clone 해야 볼 수 있는 것"으로 줄어든다
- 저장소를 private 으로 전환 — 과거 객체 접근이 함께 닫힌다. 다만 공개 기록이라는 프로젝트 성격과 상충
- 본인·보호자 동의 여부 확인 — **사실관계 미확인**

### 결정 필요

**사용자 판단 사항이다.** 승인 전까지 history rewrite·force push 를 하지 않는다.

## 4. 재발 감지 — 최소 후속 작업

**새 모니터링 시스템을 도입하지 않는다.** 현재 AWS·애플리케이션 구조에서 가장 단순한 것만.

### 4-1. 알람 (ESSENTIA 소관, 이미 구성됨)

| 알람 | 조건 | 상태 |
|---|---|---|
| RDS 커넥션 경고 | ≥ 60, 5분×2 | ✅ 구성 · 발화·메일 도달 확인 |
| RDS 커넥션 위험 | ≥ 85, 5분×1 | ✅ 구성 |
| RDS 여유메모리 | < 60MB, 5분×3 | ✅ 구성 |
| RDS 여유스토리지 | < 3GB, 5분×1 | ✅ 구성 |

**ICAROS 수신 추가가 유일한 미결이다** (§A3).

### 4-2. FATAL 로그 확인 — 도구 없이 되는 것

RDS 로그에 `log_line_prefix = %t:%r:%u@%d:[%p]:` 가 이미 설정돼 있어 **FATAL 줄마다 사용자와
클라이언트 IP 가 찍힌다.** 별도 수집 없이 조회할 수 있다:

```
aws rds download-db-log-file-portion --db-instance-identifier <ID> \
    --log-file-name <FILE> | grep FATAL
```

08-27 원인 규명이 전부 여기서 나왔다. **CloudWatch 익스포트를 켜지 않아도 된다.**
현재 ESSENTIA 만 이 명령을 돌릴 수 있다.

### 4-3. 배포 직후 확인 (사람이 하는 절차)

배포 후 **5–10분** 안에 커넥션이 60을 넘지 않았는지 본다.
알람이 그 역할을 하므로 **울리지 않았다면 통과**다. 별도 조회가 필요하면 §4-2.

### 4-4. production smoke — 스크립트 1개

DB 를 타는 것과 안 타는 것을 **갈라서** 확인한다. 갈라야 DB 장애와 배포 실패가 구분된다.

| 경로 | DB | 확인 |
|---|---|---|
| `/` | ○ | 200 · 패널 렌더 |
| `/rocket` | ○ | 200 · 시리즈 탭 |
| `/rocket/<slug>` | ○ | 200 · `rocket_series` 조인 라벨 |
| `/posts` | ○ + 상류 | 200 |
| `/api/media/<id>` | ○ | 200 · `x-vercel-cache` 상태 |
| `/_next/image?url=/api/media/<id>` | ○ | 200 |
| `/admin` | ○ | 200 (로그인 화면) |
| `/nonexistent` | ✗ | **404** — 200 이면 soft-404 회귀 |
